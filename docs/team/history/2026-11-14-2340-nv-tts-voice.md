# NV: Faraday's voice: fixed seed, cache, pre-render, audition (2026-11-14 23:40)

Owner item 6. Built on Windows with a fake `argmax-cli`; the Mac confirms by ear.

## Why the voice changed mid-run

`argmax-cli tts` picks a **random seed for every line** unless `--seed` is given (`Sources/ArgmaxCLI/TTSCLI.swift`: "Always use a seed for reproducibility -- generate one if not provided"). Temperature defaults to 0.9. So every line was a fresh roll of the dice.

The flags below are confirmed in the CLI source (argmax-oss-swift main, read with `gh api`): `--seed`, `--temperature` (default 0.9), `--top-k` (default 50), `--model 0.6b|1.7b`, `--instruction` (1.7B only; the 0.6B ignores it), `--output-path`, `--output-format m4a|wav`, `--play`.

## What changed (`hardware/speech.py` `ArgmaxTTS`)

- **`tts.mac.voice`** adds the flags to every line: `{"seed": 7, "temperature": 0.6, "top_k": 50, "model": "0.6b", "instruction": null}`. Same speaker (aiden) always. If an older argmax-cli refuses the flags ("Unknown option"), the line is retried once without them, so Faraday never goes silent.
- **No more `./output.m4a`:** the CLI also wrote it on every `--play`. Each line is now saved as a wav in a temp folder.
- **Cache (`cache/tts/`, gitignored):** that wav goes into the cache, keyed by the words and the voice settings. A line already cached plays from the file: instant and identical. The cache holds up to 400 files, oldest dropped first.
- **Pre-render at startup:** `integration/fixed_lines.py` reads Dell's fixed lines from his source with `ast` (read-only): UPPERCASE string constants that read like sentences, `_speak("...")` literals, and a `FIXED_LINES` list if Dell adds one. Today that is 20 lines: greetings, mode lines, the alarm and warning lines, "Let me look.", and so on.
  - The app renders the missing ones in the background, one `argmax-cli` run each. It pauses whenever Faraday is busy talking.
  - Lines the scan misses are cached after their first use.
- **`python3 -m hardware.tts_audition`** (on the Mac):
  - It renders one greeting with 9 takes on the 0.6B (seeds 7/42/2026 × temperatures 0.3/0.6/0.9) and 2 on the 1.7B with "Speak calmly and warmly".
  - It times each take, including the model load, and prints the range per model.
  - It plays them numbered and saves the table to `captures/tts_audition/takes.json`.
  - `--pick N` prints the exact `"voice": …` line for settings.json.

## Settings (Mac `config/settings.json`, under `"tts"` → `"mac"`)

Add after the `"command"` line (put a comma after the command's closing `]`):

```json
      "voice": {"seed": 7, "temperature": 0.6, "top_k": 50, "model": "0.6b", "instruction": null},
      "cache": true,
      "prerender": true
```

After the audition, replace the `"voice"` line with the one `--pick` prints. If you choose the 1.7B, its first run downloads the model, so do that with Wi-Fi on. If you change the voice later, the cache keys change, so the old takes are simply not used.
