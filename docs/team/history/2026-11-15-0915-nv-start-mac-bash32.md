# NV: start_mac.sh on macOS bash 3.2 (09:15, after the freeze, owner-approved fix)

**Bug:** on the Mac, `integration/start_mac.sh` stopped with "line 367: unexpected EOF while looking for matching `''". macOS `/bin/bash` 3.2 scans a heredoc inside `$( )` as shell text, so the apostrophe in "isn't" (a comment added in #75, in the device-check heredoc) opened a quote that never closed. Git Bash 5.x on Windows parses it fine, so the tests didn't catch it.

**Fix:** no apostrophes left in any heredoc inside `$( )`. The Python there prints the same text (`{m!r}`, joins computed first, `name = i["name"]`); one message now says "cannot tell which models are loaded". New test `integration.tests.test_start_mac.Bash32` fails if an apostrophe comes back (it fails on the old script). On the Mac: `/bin/bash -n integration/start_mac.sh` prints nothing.

**Outlet 2 (owner, FYI, no code change):** never a toggle. Its two .sub files were mislabelled on the Flipper (the "off" file held the ON signal); the owner renamed them, so the normal mapping works and `lights_off_at_start` is true again. `hardware.check outlets` called it "toggles": with swapped files, if the first OFF is missed while the lamp is already off, the second OFF turns it on, which reads as "right, then a repeat undid it". Known limit, left as is past the freeze. A later fix: only call it a toggle when the first send of the pair visibly changed the lamp.
