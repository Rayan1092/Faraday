# Listen button (Dell, item 7)
- Laptop / branch / PR: Dell / `dell/listen` / PR "Listen button"
- What changed:
  - **Button:** push-to-talk is gone. The dock has a small **Listen** tap button instead. One tap posts `/api/listen`, which calls integration's `board.listen_hook()` (already set to `app.voice.listen_once`). It replies `{"opened": false}` if a window is already open. `/api/talk` stays as an alias, and `talk_hook` still works.
  - **Mic indicator:** while the mic is open, the button reads "Listening…" in green and a small breathing green mic sits next to "Live" in the status card. It follows `board.listening_hook()` when integration sets it (state field `listening`), otherwise it shows for 8 s after a successful tap.
  - **Docs:** PLAN Cross-laptop row (Q26 Listen half accepted; asks NV for `listening_hook`) and the dashboard README.
- How it was tested: `python -m unittest discover` passes. New `dashboard/tests/test_listen.py`: hidden and 503 without a hook, one window per tap, the old route and hook, the indicator following the hook (and staying unknown if the hook throws), no Talk button left. The old push-to-talk test was removed. Screenshots at 1280×720 (listening) and 1920×1080 (idle).
