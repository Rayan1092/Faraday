# For Dell: demo step 3 doesn't save the visitor's message (with a ready patch)

- **From:** NV. `brain/` is Dell's folder, so NV didn't change it. The fix comes as a tested patch next to this note: [2026-11-14-1625-step3-save-message.patch](2026-11-14-1625-step3-save-message.patch).
- **Found in:** NV's live run of the full demo (`py -m integration --fake`, Bonsai `ternary-bonsai-2-4b@q2_0`), noted in the NV handoff at 15:55.

## What happens
1. Away mode. The doorbell rings, and Faraday says "Hello, I'm Faraday. What can I do for you?" then "Would you like to leave a message?".
2. The visitor says "Package for Sam, I left it by the side door."
3. Bonsai answers with **another greeting** and doesn't call `save_message`. **The message is lost.** The offline fallback does save it, so this only happens with Bonsai on.

Still happens on `main` after PR #10. Repro, no LM Studio needed:

```python
from shared import make_action, make_event, EventType, Source, ActionType
from brain.tests.helpers import make_brain, tool_calls
offer = make_action(ActionType.SPEAK, {"text": "Would you like to leave a message?"}, Source.BRAIN).to_dict()
ev = make_event(EventType.SPEECH_HEARD, {"text": "Package for Sam, I left it by the side door."}, Source.SPEECH)
d = make_brain(tool_calls(("speak", {"text": "Hello, I'm Faraday. What can I do for you?"}))).decide(ev, "away", [offer])
print([(a.type, a.args) for a in d.actions])   # main: only the greeting, no save_message
```

## Why
`Brain._keep_promised_message` (brain/core.py) saves the visitor's words in plain code only when **Bonsai's own reply** contains the word "message". Here Bonsai's reply was a plain greeting, so the safety net never fired. It doesn't look at what Faraday had *just asked*.

## The patch (brain/core.py plus a new test)
- `_keep_promised_message` now also gets `recent`.
- If the last thing Faraday said is an offer, the visitor's reply is saved as the message. An offer means the line mentions "message" and ends with "?", as in "Would you like to leave a message?".
- Bonsai's off-topic speech is then replaced with `fb.MESSAGE_SAVED` ("Thank you. I saved your message.").
- **Not saved:**
  - Plain refusals ("No thanks", "Nope.", "Not now, thanks"). A message that merely starts with "No, …" is still saved.
  - Anything after a confirmation like "Thank you. I saved your message." (not a question).
  - Home mode, where `save_message` isn't allowed.
  - Turns where Bonsai already saved it: left alone.
- New test: `brain/tests/test_offered_message.py`, 7 cases including the exact demo line.

Apply it:

```
git apply docs/team/history/2026-11-14-1625-step3-save-message.patch
python -m unittest discover
```

Checked by NV on a throwaway copy of `main` (`ce453a6`):

- **222 tests pass** (main's 215 plus the 7 new ones).

- One case the new test caught while writing the patch: an earlier draft would also have saved "Bye!" said after "Thank you. I saved your message.". That's why the offer must be a question.
