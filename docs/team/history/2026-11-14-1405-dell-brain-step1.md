# Brain + sim, Step 1 (brain works end to end on fake events)
- Laptop / branch / PR: Dell / `dell/brain` / PR "brain + sim: Step 1"
- What changed: `brain/` (Bonsai tool calling, guard rails, rule-based fallback, passphrase gate in `brain/safety.py`), `sim/` (keyboard simulator, `python -m sim`), 31 tests in `brain/tests/`. Open Questions 16–20 added to PLAN.md. Merged main (`alert_changed`): the brain answers it in plain code with no actions and no model call.
- How it was tested: sim + stand-ins only, which doesn't sign anything off. `python -m unittest discover` passes 44/44 (31 brain + 13 shared) on Windows with Python 3.13. Live demo script ran against LM Studio at 127.0.0.1:1234 with `ternary-bonsai-2-4b@q2_0`.
- What works: every demo step gives the right actions. Bonsai calls take about 4–10 s on this box (a trivial 15-token request already takes 1.7–4 s, so most of that is the server). The model picks the right action itself in about 5 of 7 demo cases. The rest are caught by the guard (it keeps trying `set_mode home`) and covered by the fallback. Disarm requests and the passphrase never reach the model.
- What's broken or faked: Bonsai 2 is a thinking model, so we send `reasoning_effort: "none"`. Without it, it uses all 200 tokens thinking and calls no tool. Hardware actions only print. `photo_described` is faked by the sim. `summarize_log` is returned but not run yet (Step 4). There's no alert state (warning/alarm) yet: that belongs in `modes/`, and the sim doesn't send `alert_changed`. Spoken greetings from the 4B are sometimes odd.
