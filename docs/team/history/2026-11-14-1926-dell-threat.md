# Threat assessment (Dell, item 1)
- Laptop / branch / PR: Dell / `dell/threat` / PR "threat assessment"
- What changed:
  - **New event:** `threat_assessed` (`shared/events.py`, FORMATS.md, format tests). Owner approved.
  - **`brain/threat.py`:** the fast Bonsai classifies each photo as delivery, visitor, suspicious or nobody through one forced-choice tool. Inputs: description, mode, time of day, why the photo was taken, recent doorbell/motion, and the voice count once NV adds it. Code validates the answer:
    - strong warning signs (a mask, a crowbar, trying the handle...) make it suspicious, whatever Bonsai says,
    - "nobody" is rejected if a person is described,
    - rules decide if Bonsai can't.
  - **Pipeline:** the label is made right after `photo_described`, before the greeting. "One moment, please." still goes first for a doorbell visitor.
  - **Effects:**
    - delivery → drop-off instructions (code adds them if Bonsai forgets),
    - visitor → message offer,
    - suspicious or nobody → no greeting.
    - `suspicious` while armed → `modes/` raises normal to warning, and the confrontation comes early (one per photo). It never lowers an alert, switches lights off, changes the mode or disarms. The stale-confrontation check now drops a line only if the house was disarmed.
  - **Shown:** under the photo (a pill with the reason), in the photo's Activity entry, in the log, and in the summary.
  - **Bench:** 5 threat cases. PLAN.md has a new "Cross-laptop hooks and fields" table, including `speech_heard.voices` for NV.
- How it was tested: `python -m unittest discover` passes 303 (1 skipped). 15 new threat tests: rules, parsing, code checks, escalate-only, pipeline effects, dashboard and summary. Live on the 4B, the threat cases scored 15/15, at 3.9 s average.
- Note: `integration.tests.test_app.Flow.test_reconnect_during_alarm_restores_red` (NV) failed once in a full run, then passed 5 times. It's timing-sensitive.
