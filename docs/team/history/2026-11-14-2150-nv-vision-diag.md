# NV: vision diagnostics (2026-11-14 21:50)

**Mac check:** `hardware.check camera` took the photo, but the description was "Photo saved.", so Bonsai 9B vision failed.

What the code did before this PR:
- It used the profile's `model` (the 9B with profile `mac`, never the 2B).
- It sent a 512 px JPEG as a base64 data URL to `/v1/chat/completions`, with a 30 s timeout (`llm.vision_timeout_s`, else `timeout_s`) and **`max_tokens` 60**.
- An empty answer gave "Photo saved." without any message. Likely cause: the 9B thinks despite `reasoning_effort: none` and uses up all 60 tokens.

Changes:
- The default `max_tokens` is now 300, settable as `llm.vision_max_tokens` (optional, read in code; not added to config).
- A failed or empty answer now logs the reason: finish_reason, reasoning length, timeout, or LM Studio's error body. The reason is also kept in `Vision.last`.
- An unclosed `<think>` is no longer taken as the description.
- New `python3 -m hardware.check vision [photo]` prints the model, LM Studio's state and type for it (`vlm` = takes images), the loaded models, the image size, time taken, HTTP status, finish_reason, the raw answer and the reason for a failure.
- `hardware.check camera` now prints the vision failure reason.

Tests: `hardware/tests/test_camera.py` (`VisionClient` thinking, timeout and error cases; `CheckVision`).
